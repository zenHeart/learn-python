## 概念 1：数字有四种形态，`/` 永远给 float

### 我当前已知的前置

JS 里只有 `number` 一种数字类型，`1` 和 `1.0` 没有区别。我假设 Python 一样。

### 逐个符号

| 符号 | 含义 | 来自 |
|------|------|------|
| `1` | int，任意精度（不会像 JS 那样溢出成浮点） | `number/converter.py` |
| `1.1` | float，双精度二进制浮点 | 同上 |
| `1j` | complex 虚数字面量，Python 用 `j` 不用 `i` | 同上 |
| `1e5` | 科学计数法，**结果类型是 float** | 同上 |
| `0b1011` / `0o17` / `0xff` | 二 / 八 / 十六进制字面量，大小写不敏感 | 同上 |
| `1_000_000` | 下划线分隔，纯粹给人看，值不变 | 同上 |
| `/` | 真除法，**两边都是 int 也得 float** | `number/operator.py` |
| `//` | floor 除法，向负无穷取整 | 同上 |
| `%` | 取模，**结果符号跟随除数** | 同上 |
| `**` | 幂运算，支持负指数和浮点指数 | 同上 |

### 预测（运行前写下）

```
1.1 + 1.2   → 2.3
1e5         → 100000
2 / 3       → 0.6666666666666666
2 // 3      → 0
-7 // 2     → -3        ← 我按 JS 的 Math.floor 直觉猜的
-7 % 2      → -1        ← 我按 JS 的 % 直觉猜的
```

### 实际运行

```
1.1 + 1.2   → 2.3
1e5         → 100000.0     ← 不是 100000，类型也变了
-7 // 2     → -4           ← 不是 -3
-7 % 2      → 1            ← 不是 -1
```

**四条预测错了两条**，而且错的是同一条规则：`//` 和 `%` 不是「去掉小数部分」，
是**向负无穷取整**。所以 `-7 // 2 = -4`，余数 `-7 - (-4)*2 = 1`。
JS 里 `Math.floor(-7/2)` 也是 -4，但 `-7 % 2` 在 JS 里是 -1——**Python 的 `%`
和 JS 的 `%` 结果符号规则不同**，这是我从 JS 迁移过来最容易写错的一处。

### 新例子：`divmod` 一次拿到商和余数

```python
print(divmod(-7, 2))    # (-4, 1)
print(divmod(7, -2))    # (-4, -1)  ← 余数符号跟随除数 -2
```

### 反例：`//` 不保证返回 int

```python
print(17 // 3, type(17 // 3).__name__)      # 5 int
print(17.0 // 3, type(17.0 // 3).__name__)  # 5.0 float
```

`examples/_draft/21.types-number.py` 的注释写 `// divide operatr always a
floor divide, return a integer`。**「return a integer」是错的**：有一边是
float 时，`//` 返回 float。已修（D-28）。

### 怎样证明我理解了

1. 能预测 `-7 // 2` 和 `-7 % 2`，并说出为什么不是 -3 和 -1。
2. 能说出 `1e5` 的类型（float）和 `2/3` 的类型（float）。
3. 能说出 `0b1011`、`0o17`、`0xff` 的值（11、15、255）。

## 概念 2：浮点不精确，`==` 不能用来比浮点

### 我当前已知的前置

JS 里 `0.1 + 0.2 === 0.3` 也是 `false`，我听说过这件事。

### 教程/示例怎么说

`examples/number/float.py` 全文只有一行：

```python
print(0.1 + 0.1 + 0.1 == 0.3)  # False
```

### 逐个符号

| 符号 | 含义 |
|------|------|
| `0.1` | 二进制浮点**无法精确表示**的十进制小数 |
| `+` | 三次累加，每次都可能再引入一次舍入 |
| `==` | 精确相等比较，不看「差多少」 |

### 实际运行

```
False
```

把中间值打出来看根因：

```python
print(repr(0.1 + 0.1 + 0.1))   # 0.30000000000000004
print(repr(0.1 + 0.2))         # 0.30000000000000004
```

**根因**：`0.1` 在二进制里是无限循环小数，存储时已经被舍入。累加把误差放大了。
这不是 Python 的 bug，是 IEEE 754 双精度的固有性质，JS 完全一样。

### 新例子：要比浮点就先 round，或用 `math.isclose`

```python
print(round(0.1 + 0.1 + 0.1, 2) == 0.3)          # True
import math
print(math.isclose(0.1 + 0.1 + 0.1, 0.3))        # True
```

### 反例：不是所有「看起来该相等」的都出错

```python
print(1.1 + 1.2 == 2.3)     # True —— 这次恰好相等
print(0.0 == -0.0)          # True —— 正负零相等
print(float('nan') == float('nan'))   # False —— nan 连自己都不等
```

`examples/number/converter.py` 第一行注释写 `print(1.1 + 1.2) # 1.3`。
**实际输出 `2.3`**，注释把结果写错了（已修，D-19）。这条正好和上面的
`1.1 + 1.2 == 2.3 → True` 对上：`1.1 + 1.2` 恰好能被精确表示成 `2.3`。

### 怎样证明我理解了

1. 能说出 `0.1 + 0.2 == 0.3` 为什么是 `False`（二进制无法精确表示 0.1）。
2. 能说出要比浮点应该怎么办（`round` 后比、或 `math.isclose`）。
3. 能预测 `float('nan') == float('nan')`（`False`）。

## 概念 3：字符串字面量 — 引号、转义、r-string、三引号

### 逐个符号

| 写法 | 含义 | 来自 |
|------|------|------|
| `'...'` / `"..."` | 单双引号**完全等价**，可嵌套 | `string/quote.py` |
| `\n` / `\t` / `\\` | 换行 / 制表 / 字面反斜杠，**各算 1 个字符** | `string/escape.py` |
| `r'...'` | raw string，反斜杠不转义 | `string/escape-r.py` |
| `"""..."""` | 三引号，可跨行 | `string/string-literal.py` |
| 行首 `\` | 续行符，把换行吞掉 | `string/string-literal.py` |

### 预测

```
print('\\')            → \
len(r'test\nbreak line') → 16     ← 我猜 15，跟转义版一样
```

### 实际运行

```
print('\\')              → \
len('test\nbreak line')  → 15     （\n 是 1 个字符）
len(r'test\nbreak line') → 16     （\ 和 n 是两个字符）
```

预测对了一半：r-string 里 `\n` 确实是两个字符，长度 16。

### 新例子：r-string 的边界

```python
print(r'\\')          # \\  （两个字符）
print(len(r'\\'))     # 2
```

### 反例 1：r-string 不能以奇数个反斜杠结尾

```text
r'abc\'    → SyntaxError: unterminated string literal
```

raw string 的反斜杠仍然会转义紧跟它的引号——只是不当成转义序列。
这条没有任何示例提到，是我自己撞出来的。

### 反例 2：单引号字符串不能跨行

```text
x = 'a
b'        → SyntaxError
```

跨行必须用三引号，或者行首加 `\`。

### 反例 3：示例自己的注释给输出加了不存在的反斜杠

`examples/string/quote.py` 第三行：

```python
print('"Isn\'t," they said.')   # 注释写: "Isn\'t," they said.
```

**实际输出是 `"Isn't," they said.`**——`\'` 的转义在词法阶段就处理掉了，
反斜杠不出现在输出里。注释让人以为输出带反斜杠。已修（D-20）。

### 怎样证明我理解了

1. 能说出 `len('a\nb')` 和 `len(r'a\nb')`（3 和 4）。
2. 能说出 `"""..."""` 和 `#` 的区别（见 [L1 走查笔记](/walkthrough/l1) 概念 3）。
3. 能说出 `r'abc\'` 为什么报错。

## 概念 4：索引与切片 — 前闭后开，越界行为不同

这是 L2 里**我最容易错**的一处，因为「下标」和「切片」对越界的处理完全不同。

### 逐个符号

| 写法 | 含义 | 来自 |
|------|------|------|
| `s[0]` | 第 1 个字符，从 0 开始 | `string/index.py` |
| `s[-1]` | 倒数第 1 个字符 | 同上 |
| `s[a:b]` | **左闭右开**：取 `a` 到 `b-1` | `string/slice.py` |
| `s[a:]` / `s[:b]` | 省略一端 | 同上 |
| `s[::2]` | 步长 2 | 走查补充 |
| `s[::-1]` | 负步长 = 反转 | 走查补充 |

### 预测

```
'python'[0:2]    → py
'python'[-2:-1]  → o
'python'[7:9]    → 报错？     ← 我猜越界会抛异常
'python'[-10:9]  → 报错？     ← 我猜负越界会抛异常
```

### 实际运行

```
'python'[0:2]    → py
'python'[-2:-1]  → o
'python'[7:9]    → （空字符串，不报错）
'python'[-10:9]  → python（负越界被裁剪成 0）
'python'[::2]    → pto
'python'[::-1]   → nohtyp
```

### 新例子 + 反例：下标越界报错，切片越界被裁剪

```python
s = 'python'
print(s[7:9])      # ''  —— 切片宽容
print(s[6])        # IndexError: string index out of range  —— 下标严格
```

**同一個「越界」，两种行为。** 记住的办法：切片是「取一段」，取不到就给你空的；
下标是「要这一个」，没有就是没有。

`examples/string/slice.py` 里 `print(a[7:9])` 这行**没有注释**，
运行结果是空行——初学者看到空行会以为程序坏了。已补注释（D-21 同轮）。

### 怎样证明我理解了

1. 能说出 `'python'[1:3]` 为什么是 `'yt'` 不是 `'yth'`（右开）。
2. 能预测 `'python'[10]`（`IndexError`）和 `'python'[10:]`（`''`）。
3. 能说出 `'python'[::-1]` 的结果（`'nohtyp'`）。

## 概念 5：字符串运算 — `*` 优先于 `+`，相邻字面量会自动拼

### 逐个符号

| 写法 | 含义 | 来自 |
|------|------|------|
| `'a' + 'b'` | 拼接，**只能 str + str** | `string/operator.py` |
| `'ba' * 2` | 重复 | 同上 |
| `'ba' 'na'` | 相邻字面量在**编译期**拼接，运行期没有 `+` | 同上 |

### 预测

```
'ba' + 'na'*2   → 'banana'      ← 我猜从左到右，得 'bana'na' 报错
'ba' 'na' "na"  → 'banana'
```

### 实际运行

```
'ba' + 'na'*2   → banana     （* 优先级高于 +，和数学一样）
'ba' 'na' "na"  → banana
```

### 反例 1：str 不能和 int 相加（JS 可以）

```python
'a' + 1          # TypeError: can only concatenate str (not "int") to str
'10' + '20'      # '1020'  —— 不是 30
int('10') + int('20')   # 30
```

**这是 JS 迁移过来第二个大坑**：JS 里 `'a' + 1` 得到 `'a1'`，Python 直接报错。

### 反例 2：`*` 的因数是浮点会报错

```python
'ab' * 2.0       # TypeError: can't multiply sequence by non-int of type 'float'
```

### 怎样证明我理解了

1. 能说出 `'ba' + 'na' * 2` 的计算顺序和结果。
2. 能说出 `'a' + 1` 的结果（`TypeError`）以及正确写法。
3. 能说出 `'ab' 'cd'` 是不是运行期拼接（不是，编译期）。

## 概念 6：列表 — 原地修改的方法都返回 `None`

### 逐个符号

| 方法 | 作用 | 返回值 | 来自 |
|------|------|--------|------|
| `append(x)` | 末尾追加 | `None` | `list/list_add.py` |
| `insert(i, x)` | 位置 i 插入 | `None` | 同上 |
| `+` | 生成**新**列表 | 新 list | 同上 |
| `*` | 重复生成新列表 | 新 list | 同上 |
| `remove(v)` | 删第一个匹配的值 | `None` | `list/list_del.py` |
| `del l[i]` | 删指定下标 | 语句，无返回值 | 同上 |
| `pop(i)` | 删并**返回**该位置的值 | 被删的值 | 同上 |
| `l[i] = v` | 改元素 | — | `list/list_modify.py` |
| `sort()` | 原地排序 | `None` | `list/list_order.py` |
| `sorted(l)` | 返回排好的新列表 | 新 list | 同上 |
| `reverse()` | 原地翻转 | `None` | 同上 |

### 预测

```
list = [1, True, 'tom']
list.append('jack')
print(list.append('x'))    → None       ← 我猜返回新列表
```

### 实际运行

```
append 之后原列表被改，append 的返回值是 None
```

**「返回 `None`」是 Python 的刻意设计**：方法已经改了原对象，再返回一个新列表
会诱导人写成 `l = l.append(x)`，然后 `l` 变成 `None`。

### 新例子：`+` 和 `append` 的区别

```python
a = [1, 2]
b = a + [3]
print(a, b, a is b)     # [1, 2] [1, 2, 3] False

c = [1, 2]
c.append(3)
print(c)                # [1, 2, 3]  —— c 自己被改了
```

### 反例 1：`[x] * n` 复制的是**引用**，不是对象

```python
x = [[]] * 3
x[0].append(1)
print(x)                # [[1], [1], [1]]  —— 三个都变了
print(x[0] is x[1])     # True
```

这条没有任何示例讲，但它是「可变对象 + 乘法」最常踩的坑。
`[1] * 5` 没事是因为 int 不可变；换成 list 就出事。

### 反例 2：混类型不能排序

```python
[1, 'a'].sort()         # TypeError: '<' not supported between instances of 'str' and 'int'
```

`list_order.py` 的注释写「注意 list 必须为同一类型否则会报错」——**这条是对的**，
实测确认抛 `TypeError`。

### 反例 3：`sort()` 排的是码位，不是「字典序」

```python
sorted(['A', 'tom', 'jerry', 'jack', '1'])
# ['1', 'A', 'jack', 'jerry', 'tom']
```

顺序来自字符编码：`'1'`(49) < `'A'`(65) < `'a'`(97) < `'j'`(106)。
所以**数字 < 大写 < 小写**，和「人类字典序」不是一回事。
`list_order.py` 的注释原写「字典排序」，词不达意，已改成「按字符编码排序」（D-22）。

### 怎样证明我理解了

1. 能说出 `l.append(x)` 的返回值，以及为什么这么设计。
2. 能预测 `a = [1,2]; b = a + [3]` 之后 `a` 的值。
3. 能预测 `x = [[]] * 3; x[0].append(1)` 之后 `x`。
4. 能说出 `sorted(['1','A','a'])` 的顺序和原因。

## 概念 7：字典 — `in` 看键，`items()` 是动态视图

### 逐个符号

| 写法 | 含义 | 来自 |
|------|------|------|
| `{'k': v}` | 字面量，`{}` 是 dict、`{1,2}` 是 set | `map/map_init.py` |
| `{name: v}` | 键可以是**变量表达式**，不是字面名字 | 同上 |
| `m['k'] = v` | 新增或修改，同一个写法 | `map/map_add.py` |
| `del m['k']` | 删键 | `map/map_del.py` |
| `m.items()` / `keys()` / `values()` | 视图对象，可for循环解包 | `map/map_search.py` |
| `m.get(k, d)` | 取不到返回默认值，不抛异常 | 走查补充 |

### 预测

```
map = {'name': 'tom'}
'name' in map      → True
'tom' in map       → True       ← 我猜值也算成员
items = map.items()
map['age'] = 12
list(items)        → [('name','tom')]   ← 我猜视图是快照
```

### 实际运行

```
'name' in map      → True
'tom' in map       → False      ← in 只看键
list(items)        → [('name', 'tom'), ('age', 12)]   ← 视图是动态的
```

### 新例子：键的顺序就是插入顺序

```python
print(list({'b': 1, 'a': 2}.keys()))    # ['b', 'a']  —— 3.7+ 保证
print({'a': 1, 'a': 2})                 # {'a': 2}    —— 重复键后者赢
```

### 反例：取不存在的键抛 `KeyError`，`.get()` 不会

```python
d = {'a': 1}
d['z']           # KeyError: 'z'
d.get('z')       # None
d.get('z', 0)    # 0
```

### 示例注释的三处错（已修）

| 文件 | 原注释 | 问题 |
|------|--------|------|
| `map/map_add.py` 等 5 个 | 「采用方括号初始化**列表**」 | 代码建的是**字典**，复制粘贴串文件了 |
| `map/map_search.py` | 「采用 **in** 遍历字典」 | 该行上方根本没有 `in`，注释错位 |
| `map/map_search.py` | 「items 返回**二维数组**模式」 | 返回的是 `dict_items` 视图，元素是 `(键, 值)` 元组，不是二维数组 |
| `map/map_modify.py` | 「修改**元祖**数值」 | 「元祖」是「元组」的错别字，且这里是字典 |

### 怎样证明我理解了

1. 能说出 `'tom' in {'name': 'tom'}` 为什么是 `False`。
2. 能说出 `d.items()` 是快照还是视图（视图，后加的键也看得到）。
3. 能说出 `{}` 和 `{1, 2}` 的类型（`dict` / `set`）。
4. 能说出取不存在键的两种结果（`KeyError` / `None`）。

## 概念 8：列表推导式 — `for` 后面跟 `if` 是过滤

### 逐个符号

`[ double(el) for el in a if is_even(el) ]`

| 部分 | 含义 |
|------|------|
| `double(el)` | 输出表达式，每个元素变成什么 |
| `for el in a` | 遍历，和 for 循环同序 |
| `if is_even(el)` | 过滤条件，**写在 for 之后** |

### 预测

```
a = range(1, 15)
[el*2 for el in a if el % 2 == 0]
→ [4, 8, 12, 16, 20, 24, 28]      ← 注释就是这么写的，我信
```

### 实际运行

```
[4, 8, 12, 16, 20, 24, 28]
```

**注释这次是对的。** 手算复核：1..14 里的偶数是 2,4,6,8,10,12,14，各乘 2 得上述 7 个数。

### 新例子：`if/else` 要放在 `for` **前面**

```python
[el if el % 2 else -el for el in range(4)]
# [0, 1, -2, 3]     ← 偶数的位置放 -el
```

`if` 在 `for` 后面是**过滤**（可能没有输出）；`if/else` 在 `for` 前面是
**三元表达式**（一定有输出）。位置决定语义，这是推导式最容易混的一点。

### 反例：推导式有独立作用域

```text
[x for x in range(3)]
print(x)        # NameError: name 'x' is not defined
```

循环变量不会泄漏到外面——和 JS 的 `for (let x of ...)` 一致，和 Python 2 不一致。

### 怎样证明我理解了

1. 能说出 `[f(x) for x in a if p(x)]` 三部分各是什么。
2. 能说出 `if p(x)` 和 `if p(x) else q(x)` 在推导式里位置为什么不能换。
3. 能预测 `{i % 2 for i in range(4)}` 的结果（`{0, 1}`）。

## 这一轮记下的困惑与解决

| # | 困惑 | 怎么解决的 |
|---|------|-----------|
| C-09 | `-7 // 2` 我猜 -3，实际 -4 | 写成断言让 Python 判。`//` 是 floor（向负无穷），不是「截断」。JS 的 `Math.floor` 同理，但我此前把 `%` 也一起搬过来了 |
| C-10 | `-7 % 2` 我猜 -1，实际 1 | 余数符号跟随**除数**。`divmod(7, -2) = (-4, -1)` 一反一正，正好说明规则 |
| C-11 | `17 // 3` 和 `17.0 // 3` 结果一样吗 | 值一样（5），类型不同（int / float）。`//` 不保证返回 int |
| C-12 | `1e5` 打印成 `100000.0`，我以为写错了 | 科学计数法字面量**类型就是 float**。示例注释写 `# 100000` 漏了 `.0`，已修 |
| C-13 | `'python'[7:9]` 到底报不报错 | 不报错，返回 `''`。但 `'python'[6]` 报 `IndexError`。切片裁剪、下标严格 |
| C-14 | `[[]] * 3` 为什么改一个三个都变 | 乘法复制的是引用。写成断言 `x[0] is x[1] is x[2] → True` 确认 |
| C-15 | `items()` 拿到后再加键，还能看到吗 | 能。`dict_items` 是**视图**不是快照 |
| C-16 | `'tom' in {'name': 'tom'}` 为什么 False | `in` 只查键。要查值得写 `'tom' in d.values()` |
| C-17 | 推导式里 `if` 放前放后不一样吗 | 不一样。后置=过滤，前置=三元。位置决定语义 |
| C-18 | `round(2.5)` 是 2 还是 3 | **2**。银行家舍入（四舍六入五成双），`round(3.5)` 才是 4。示例从没提过 |

## 我认为 L2 素材缺的练习

1. **没有「故意写错」的练习**：`TypeError`（str+int、混类型排序）、
   `KeyError`、`ValueError`（remove 找不到）各值得亲手触发一次。
   L1 已经有「两种 ValueError 消息」的缺口记录，L2 缺口同类。
2. **没有浮点比较的练习**：`float.py` 只有一行 `== 0.3`，
   没让人试「怎么比才对」。
3. **没有 `sort` 键函数的练习**：`key=len` 这种最常见用法完全没出现。
4. **没有「原地 vs 新对象」的对照练习**：`append` / `+` / `sort` / `sorted`
   四个方法散在 3 个文件里，没有一张表把它们并排。

这四项已写进 [未解决与恢复点](/walkthrough/open) 的素材缺口清单。
