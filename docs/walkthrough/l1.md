## 概念 1：`print()` 输出

### 我当前已知的前置

JS 里用 `console.log()` 往控制台打东西。我假设 Python 的 `print()` 是同一地位。

### 逐个符号

| 符号 | 含义 |
|------|------|
| `print` | 内建函数名，把内容写到标准输出 stdout |
| `( ... )` | 函数调用，括号内是参数 |
| `"Hello world!"` | 字符串字面量，引号是语法的一部分，**不属于内容** |
| `1 + 2` | 两个 int 相加，先求值再传入 |
| `,` | 多参数分隔符 |
| `end="\n"` | 默认每次调用结束补一个换行 |

### 预测（运行前写下）

```
print("Hello world!")   → Hello world!
print(1 + 2)            → 3
print("a", "b")         → a b
print(1, 2)             → 1 2
```

### 实际运行

```
Hello world!
3
引号外 单引号也可以
不换行接在后面
被赋值的 print
print 的返回值是: None 类型: NoneType
```

四条预测全部命中。

### 新例子：证明我理解「引号不是内容的一部分」

```python
print("引号外", '单引号也可以')   # 单双引号等价
print("不换行", end="")          # end 参数抑制换行
```

### 反例：证明我理解 `print` 只写 stdout、不返回值

```python
result = print("被赋值的 print")
print(repr(result), type(result).__name__)   # None NoneType
```

**反例的意义**：如果我把 `print()` 当成「返回打印后的值」，就会写出
`x = print(...)` 然后拿 `x` 去用。实测证明它返回 `None`。

### 怎样证明我理解了

能解释这三件事且不改代码地预测对：
1. `print(1 + 2)` 为什么输出 `3` 而不是 `1 + 2`（先求值再传参）。
2. `print("a", "b")` 为什么中间有一个空格（多参数默认单空格连接）。
3. `print()` 的返回值是什么（`None`，类型 `NoneType`）。

## 概念 2：变量赋值与 f-string

### 我当前已知的前置

JS 的 `let` / `const`，变量是「盒子」。

### 逐个符号

| 符号 | 含义 |
|------|------|
| `name` | 变量名（标识符），指向右侧的对象 |
| `=` | **赋值/绑定**，把右侧值绑到左侧名字；不是「相等」 |
| `"Python"` | str |
| `18` | int |
| `True` | bool 字面量，**首字母必须大写**（JS 是小写 `true`） |
| `f"..."` | f-string，`{}` 内是表达式，求值后替换成文本 |
| `{name}` | 花括号内直接写变量名，不需要 `$` 或 `+` |

### 预测

```
我叫Python，今年18岁
```

### 实际运行

```
我叫Python，今年18岁
明年 19 岁, is_student=True, 类型=bool
a = [1, 2, 3, 4] | b = [1, 2, 3, 4] | a is b -> True
x = 5 | y = 99 | x is y -> False
小写 true -> NameError : name 'true' is not defined
```

### 新例子：f-string 里可以放表达式

```python
name = "Python"
age = 18
is_student = True
print(f"明年 {age + 1} 岁, is_student={is_student}, 类型={type(is_student).__name__}")
```

### 反例 1：可变对象的别名共享（这是我和 JS 心智模型差异最大的地方）

```python
a = [1, 2, 3]
b = a          # b 不是拷贝，是同一个对象的另一个名字
b.append(4)
# a 也变成 [1, 2, 3, 4]，a is b -> True
```

JS 里 `let b = a` 对数组同样是引用，这点一致。但 Python 的 `=` **永远**
是绑定名字，没有「值拷贝」这回事——这条对我后续理解「函数参数传递」
是关键前置。

### 反例 2：不可变对象重新赋值不影响旧名字

```python
x = 5
y = x
y = 99         # 重新绑定 y，x 不受影响，x is y -> False
```

### 反例 3：`True` 必须大写

下面这行会抛 `NameError: name 'true' is not defined`，所以用 `text` 标注、
不当成可运行块：

```text
bad = true     # NameError: name 'true' is not defined
```

### 怎样证明我理解了

1. 能预测 `b = a; b.append(4)` 之后 `a` 的值，并说出为什么。
2. 能预测 `x = 5; y = x; y = 99` 之后 `x` 的值，并说出为什么和上一条不同。
3. 能说出 `True` 写小的结果（`NameError`，不是 `False`）。

## 概念 3：注释与三引号

### 我当前已知的前置

JS 的 `//` 和 `/* */`。

### 教程怎么说

`docs/tutorial/begin.md` §3 把下面这段称作「多行注释」：

```python
# 这是单行注释
"""
这是多行注释，
通常用于文档字符串
"""
```

### 我的困惑

如果 `"""..."""` 是注释，为什么点「▶ 运行」有输出区域反馈？
它到底占不占内存？和 `#` 有什么区别？

### 查证与结论

`#` 是真正的注释，解释器直接丢弃。三引号包起来的是**字符串表达式**：
- 放在函数/模块第一行时叫 **docstring**，会被保留，可通过 `help()` 和
  `__doc__` 读到。
- 放在其他位置就是一个求值后丢弃的表达式。

教程的「多行注释」是常见简化说法，但会引出「它和 `#` 一样」的误解。
已在 `begin.md` 补了一段说明（见 [发现的问题](/walkthrough/defects) D-09）。

### 怎样证明我理解了

能回答：`"""text"""` 单独一行时 Python 做了什么？（构造一个 str 对象然后
丢弃）它和 `# text` 的区别是什么？（前者是表达式、可被 `__doc__` 读到，
后者被词法阶段直接删除）

## 我认为教程缺的练习

L1 现有练习只有 2 题，且都围绕同一个 `load_data()`。缺口：

1. 没有让学习者**故意写错**再读报错的练习（`ValueError` 的两种消息
   `not enough` / `too many` 值得亲手各触发一次）。
2. 没有考察「可变/不可变」的练习（C-02 的困惑靠我自己构造反例才解决）。
3. 没有让学习者判断「这段代码会不会有输出」的练习（站点里大量块
   `(运行完成，但没有 print 输出)`，初学者容易误判为失败）。
