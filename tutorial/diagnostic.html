诊断与掌握合同 ​

本课程不把读完页面、点击运行或自评当作掌握。每次学习前后都记录可观察证据，并用五个维度更新路线：

  • Explain：能说清因果、不变量、边界和反例。
  • Perform：从新起点独立完成一个小而真实的任务。
  • Debug：定位陌生缺陷，说明信号、根因和最小修复。
  • Transfer：改变语言、工具、约束或业务场景后仍能使用同一机制。
  • Retain：延迟后无提示重建，未复测前状态只能是 fragile。

首轮高信息量探针 ​

探针任务主要区分
P1用 Python 写一个安全的 get_or_default，处理列表、字典和空值语法、可变对象、默认参数
P2解释 JS Promise 与 Python coroutine 的执行边界，并写一个超时示例异步心智模型
P3给出一段缺少 tool_call_id 对齐的 Agent Loop，定位并修复错误协议、数据结构、调试
P4用固定 corpus 计算 hit rate、recall@3 和 MRR数据类、函数分解、评测
P5设计一个只读知识库工具的权限、审计和拒答边界业务建模、安全、迁移
P6在检索命中下降后判断是切块、召回、重排还是评测集问题诊断策略与可观测性

探针只覆盖会改变前两步路线的共享先修；通过 P1 不会自动跳过 P3 或 P5。

状态规则 ​

状态判定
unseen没有表现证据
blocked缺环境、权限或硬先修
learning正在练习或明显依赖提示
fragile立即任务通过，但解释、调试、迁移或延迟保持不足
mastered四维无提示通过且延迟保持验证

反馈合同 ​

每次失败输出：

  1. 观察到的证据；
  2. 主要错误类型：concept / procedure / strategy / attention / tool / environment；
  3. 只解释一个最小关键机制；
  4. 一个更小的修复任务；
  5. 一道去掉支架的同构题；
  6. 下一次复测的通过标准。

LLM 可以生成反馈建议，但不能仅凭对话或自评修改 canonical mastery state。
