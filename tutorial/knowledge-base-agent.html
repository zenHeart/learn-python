知识库 Agent：从 Python 到真实业务系统 ​

本案例以 Python 语法、数据契约、检索、工具调用、权限、评测和恢复构成终局验收合同。当前仓库的 教学 fixture 只实现离线词元检索、ACL、文档 ID/版本引用、拒答与评测门禁；工具循环、MCP、模型调用和恢复仍是待完成的练习，整案保持 verification: not-run。

终局任务 ​

从空目录交付一个面向脱敏测试资料的知识库 Agent：

  1. 接收问题并检索版本化知识库；
  2. 返回带文档 ID 和版本的引用；
  3. 无证据时拒答或请求人工确认；
  4. 通过只读白名单工具读取摘要；
  5. 记录 query、召回结果、工具调用、错误和耗时；
  6. 用 golden set 做 recall@k、MRR、引用覆盖率和回归门禁。

教学 fixture 使用标准库即可运行。后续练习需要自行实现 embedding、LLM API、MCP Server 和数据库适配器，并保持评测与安全合同。

系统边界 ​

用户问题
  ↓
请求契约与权限
  ↓
混合检索（关键词 / 向量 / RRF）
  ↓
证据过滤与引用
  ↓
Agent Loop
  ├─ 只读知识库工具
  ├─ 评测工具
  └─ 人工确认工具（默认停机）
  ↓
答案、引用、trace、指标

模型只能提出工具调用，不能直接访问文件、数据库或业务系统。工具执行层负责参数校验、权限检查、超时、幂等和审计。

必须掌握的机制 ​

机制需要能解释的边界故障题
数据契约类型注解不是运行时校验；外部输入必须验证非法 top_k、未知 doc_id、越权 role
Agent Loopassistant tool call 与 tool result 必须按 ID 对齐并发返回顺序改变后结果错配
检索命中率不等于答案正确；切块、召回、重排和引用是不同层评测集命中下降但关键词检索未变
权限在检索前限定授权范围，读取文档与返回引用时复核；无权内容不得进入外部重排或模型上下文高分文档属于另一个角色
重试响应丢失时先读状态，不能盲目重复副作用已写入但响应超时
评测业务成功率、检索指标、引用覆盖率和成本延迟分别度量只看 LLM 总分掩盖召回回归

分层练习 ​

  1. 最小检索：实现 tokenizer、TF-IDF 或 BM25，固定排序和 tie-break。
  2. 引用回答：答案只允许使用 top-k 证据，找不到依据时返回拒答。
  3. 工具调用：实现 get_doc 和 search_docs，校验参数并返回结构化错误。
  4. Agent Loop：使用离线 fake model 跑通 assistant → tool → assistant。
  5. 恢复故障：注入缺少 tool_call_id、超时、重复调用、非法参数四类错误。
  6. 评测门禁：新增一条 query 后指标下降，CI 必须失败。
  7. 迁移：把测试面经语料换成银行测试规则语料，增加权限和人工确认。

业务迁移到银行测试 ​

课程可以使用以下合成场景，但不能接入生产数据：

  • 手机银行转账规则与测试数据说明；
  • 测试环境账户查询接口约束；
  • UI 自动化定位策略；
  • 回归报告异常分类；
  • 需要人工确认的高影响动作。

知识库 Agent 的成功标准是“能提供可核验依据并安全停止”，不是“总能给出答案”。
